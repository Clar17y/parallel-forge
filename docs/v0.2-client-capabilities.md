# Forge v0.2 client capability matrix

Investigation date: 2026-09-10. Evidence includes official documentation, installed
client schemas and metadata-only account probes. No application model turn or login
was started; Forge did not extract or copy credentials.

## Evidence classes

* **Docs** means an official vendor documentation claim.
* **Protocol/schema** means the installed client’s local interface or generated
  app-server schema. It proves the field exists, not that an account supports it.
* **Installed** means local executable version/help output.
* **Deterministic** means a Forge-supervised fake client exercised the implemented transport; it does not prove installed-client or account capabilities.
* **Live** is deliberately `unproven`: no model call or login was authorized.

## Codex config and schema findings

Official [Codex configuration reference](https://developers.openai.com/codex/config-reference/)
documents:

* `features.shell_tool = false` disables the default shell tool.
* `features.multi_agent = false` disables `spawn_agent`, `send_input`,
  `resume_agent`, `wait_agent`, and `close_agent`.
* `web_search` is the current top-level setting. `features.web_search`,
  `features.web_search_cached`, and `features.web_search_request` are deprecated
  legacy toggles.
* `mcp_servers.<id>.enabled_tools` is an allowlist and
  `mcp_servers.<id>.disabled_tools` is a denylist for one MCP server; this does
  not disable Codex native tools.
* `forced_login_method = "chatgpt"` restricts auth to ChatGPT login.
* `history.persistence = "none"` avoids transcript persistence.

The installed CLI supports `--config key=value`, `--profile`,
`--ignore-user-config`, `--strict-config`, and app-server schema generation.
The generated `ThreadStartParams.json` records `model`, `modelProvider`,
`allowProviderModelFallback`, `approvalPolicy`, `permissions` or `sandbox`,
`runtimeWorkspaceRoots`, `serviceName`, and `dynamicTools`. It contains no
`tools`, `builtInTools`, `disableBuiltIns`, `applyPatch`, or native-tool
allowlist field. `TurnStartParams.json` similarly has model/effort/sandbox/
approval/tool-output fields but no native-tool suppression field.

The concrete isolation candidate combines `environments=[]`, dynamic Forge tools,
`allowProviderModelFallback=false`, and explicit removal of hosted tools and
inherited integrations. Absence of a global tool allowlist is not itself a blocker:
the installed schema documents environmentless operation. Upstream implementation
supports that interpretation, but installed-client isolation and billing still
require conformance proof before enabling this route.

The reproducible local schema artifact is `.llm-output/codex-schema`, generated
with:

```text
codex app-server generate-json-schema --out .llm-output/codex-schema --experimental
```

## Minimum controlled-tool additions

The native clients do not provide Forge’s required operation semantics for
repository work. The Forge broker must expose typed tools at minimum for:

* file read/list/search, with path reservations and bounded output;
* create/update/delete file and rename/move, each carrying an operation ID;
* named checks, with command identity selected by Forge policy rather than
  arbitrary shell text;
* diff/status and candidate evidence capture;
* commit/checkpoint only through the existing Forge gate;
* interruption and receipt lookup for admitted operations.

Do not enable native shell, native file tools, native apply_patch, or native
web/network tools as a substitute for these controls. Provider tool callbacks
must return a durable Forge receipt and reject stale/forged authority.

## Exact mapping and billing blockers

* `gemini-3.8-flash-medium` is not listed by the current official Gemini CLI
  model-selection documentation, which lists `gemini-2.5-*` and `gemini-3-*-preview`.
  It cannot be advertised without installed-client/account discovery and live
  proof. `agy` is a separate client.
* Codex subscription login is viable, but included usage can transition to
  purchased credits; rate-limit status is not a no-overage guarantee.
* Claude subscription login and account credit settings require verification;
  an enforced allocation-only boundary is not yet established. Forge must reject
  API-key precedence and cannot infer billing enforcement from model output.
* Gemini’s Google-account paid tiers are distinct from API-key/Vertex
  pay-as-you-go. Official CLI 0.59.0 provides `billing.overageStrategy="never"`
  to disable credit use; inherited settings and actual enforcement still need proof.
* No live proof was performed; all required provider routes remain disabled until
  separately authorized conformance and billing-boundary checks pass.

## Environmentless Codex alternative — primary follow-up

The installed schema provides a more specific alternative than a global tool
allowlist: `ThreadStartParams.environments=[]` explicitly disables environment
access, as does the per-turn override in `TurnStartParams`. The official current
[`spec_plan.rs`](https://github.com/openai/codex/blob/main/codex-rs/core/src/tools/spec_plan.rs)
gates native patch, shell and image-file tools on the presence of an environment.
A thread with no native environment and only Forge dynamic tools is therefore a
concrete supported-protocol candidate for isolation. Current upstream source is
not proof of behavior in the then-installed 0.153.4, and hosted web/apps/plugins/settings
still require separate removal and deterministic/live conformance checks.
The earlier absence of a single native-tool allowlist field does not establish
that this alternative is unavailable. Keep full isolation unproven pending that
verification rather than requiring a future schema change.

## Read-only allowance telemetry probe

`limits-probe.py` / `limits-result.json` under `.llm-output/codex-metadata/`
exercised only initialization and `account/rateLimits/read`, then terminated the
client. The installed client returned a Codex quota window (40 percent used,
10,080 minutes), no reached-limit category, and credit flags `hasCredits=false`,
`unlimited=false`. These are a point-in-time account observation, not per-attempt
usage or a provider spending cap. No model turn, credit redemption or email was
requested. The [official app-server field definitions](https://learn.chatgpt.com/docs/app-server#6-rate-limits-chatgpt)
distinguish quota windows and optional credit details. The response does not prove
a durable no-overage guarantee; allowance-only route admission remains blocked
until that boundary is established through supported controls and conformance.

Further official billing evidence confirms why a quota snapshot is insufficient:
[OpenAI's access-engine description](https://openai.com/index/beyond-rate-limits/)
describes moving from included limits to credits within one request. The
[personal-plan credit guide](https://help.openai.com/en/articles/12642688-using-credits-for-flexible-usage-in-chatgpt-freego-pluspro-sora)
also documents shared credit balances and optional automatic reload. Disabling
automatic purchases alone would not prevent spending existing credits. A supported
enforced allowance-only boundary still needs proof; Forge does not infer it from
the absence of an API key, a positive quota window or a sampled zero balance.


## Official Gemini CLI alternative

The local installation is version 0.59.0, pinned from the public official npm
package with its lockfile retained under `.llm-output/gemini-client/`. Install
scripts were disabled for this capability investigation; version/help execute
successfully. Node was 24.20.0. No authentication or model call was initiated.

The shipped configuration reference and [current official reference](https://geminicli.com/docs/reference/configuration/#billing)
both define `billing.overageStrategy="never"` as disabling AI-credit use. The
installed tool-registry implementation applies the `tools.core` allowlist to
native read, write, shell, web, skills, MCP-resource and agent tools; an explicit
empty array admits none of these built-ins. MCP discovery follows separately and
must be restricted to the bound Forge broker. These are concrete controls to test,
not a live isolation/billing claim.

Bundled model constants include Gemini 3.5 Flash but not the requested
`gemini-3.8-flash-medium`. Static constants do not establish account availability
or exclude server-discovered models. Exact account discovery and authorized live
proof remain prerequisites; no replacement mapping was made.

Strict output schema evidence: the official Structured Outputs guide requires
closed objects and all fields required, with nullable values for optional data:
https://developers.openai.com/api/docs/guides/structured-outputs . Codex 0.153.4
sets the output-schema strict flag by default in core/src/client_common.rs and
passes it through codex-api/src/common.rs (tag rust-v0.153.4 in openai/codex).
Forge now wraps the decision union in a closed root object and recursively
normalizes generated typed schemas to these constraints. Offline schema and
fake-client tests verify this shape; they do not establish live model support.


## Claude account-level allowance control — supported alternative

The [usage-credit guide](https://support.claude.com/en/articles/12429409-manage-usage-credits-for-paid-claude-plans)
explicitly states that disabling usage credits in account Settings > Usage leaves
only included plan usage available. This is a supported account-level alternative
to a per-process no-credit flag; absence of that CLI flag alone does not prove
allowance-only operation impossible. Forge has not inspected or changed this
account setting. A trusted, account-bound preflight verification mechanism and
installed-client conformance remain missing; a model claim or sampled balance
cannot substitute for the disabled-credit control.

The [Agent SDK subscription notice](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan)
says the proposed separate monthly SDK credit change was paused on June 15:
SDK, `claude -p`, and third-party app usage still use subscription usage limits.
The older text below that notice is explicitly historical and must not drive
Forge billing assumptions. Search snippets still expose superseded text.

Next capability investigation: identify a supported way to verify disabled
usage credits for the authenticated official client without extracting credentials,
then include that evidence in prelaunch capability admission and separately
scoped conformance. Production admission remains unavailable pending that proof;
this finding changes the investigation path, not the release result.

## Claude deterministic gateway evidence

The implemented gateway runs under Forge's process supervisor rather than letting
an SDK own process lifetime. Its official control/MCP exchange, structured output,
identity rejection, cancellation/deadline, observed usage and uncertain receipt
settlement are covered by a Python fake peer. All 53 focused gateway/codec cases
pass (`.llm-output/claude-supervised/adversarial/final-root-tests.txt`). Exact
capability booleans, including separately verified hook isolation, are required
before launch. No production capability verifier or live route was enabled.

[Official hook documentation](https://code.claude.com/docs/en/hooks) describes
