## Frozen profile and proof classes

The requested profile is dated **10 September 2026**. Requested identities are
OpenAI Astra low for primary orchestration and direct trivial repairs; Gemini
`gemini-3.8-flash-medium` for routine writing; OpenAI Luna medium as its approved
fallback; OpenAI Terra low for complex implementation; Claude `claude-opus-5`
medium for independent review; OpenAI Sol low for planning/adversarial tests and
Sol high for security or a distinct high-risk correctness question. A result
records requested and effective identity separately. Unsupported aliases require
an explicit operator-approved mapping and are never silently relabelled.

Two proof classes are deliberately separate:

- **Deterministic proof** uses scripted adapters, real PostgreSQL, real API and
  worker processes where the tested boundary requires them, controlled tools and
  local Git repositories. It proves state, authorization, recovery, accounting
  and adapter contract behavior; it never proves a subscription or model exists.
- **Live proof** is separately authorized and uses the production runtime factory,
  official signed-in client and the same controlled tools against a disposable
  copy of the frozen fixture. It records client/version, authentication status,
  requested/effective model and effort, billing mode, tool capability, candidate
  and receipts. A read-only call does not prove write/check capability.

Full v0.2 acceptance requires live OpenAI primary orchestration and selected
specialist/direct-repair roles, Gemini writing and validation, and Claude
read-only independent review. Every adapter also requires deterministic negative
cases. Missing required live proof is a release blocker, not a deterministic
failure.

OpenAI live conformance uses the operator's existing personal ChatGPT login,
selected on 13 September 2026. Authentication/catalog metadata alone cannot satisfy
the allowance-only billing or native-tool isolation assertions. A rejected
capability configuration remains unavailable, distinct from confirmed exhaustion.
This account selection does not change the frozen scenarios or authorize live
calls, paid credits, CI reruns or release actions.

Codex configuration cases include published structured feature tables with
`enabled: false`. Missing/nonboolean/enabled values and structured values supplied
for scalar-only gates reject before a thread; billing and MCP checks still apply.

The deterministic Gemini launch cases additionally inspect the real supervised
child's settings/environment and ACP working directory. They require an explicit
client home, empty dotenv guards for both trust outcomes, ordinary tool/hook/skill
and credit controls, and the Forge-only MCP name/extension arguments. Concurrent
attempts share the configured auth home but retain distinct launch directories;
cleanup never touches that home. Collision, partial setup, replaced-directory,
unexpected-evidence and uncertain-settlement cases preserve ownership and receipts.
An offline source characterization executes pinned client snippets with a fake
filesystem and fixture schema/defaults to check their relevant semantics. It does
not import or run the CLI/SDK, read credentials, validate the whole client schema
or establish account, remote-policy, auxiliary-model or live billing conformance.
These are additional adapter checks, not a change to the frozen scenario inputs.

## Repository and command fixtures

All repositories start on `main`, have `.gitignore` containing `.forge/` and
`.worktrees/`, and use `Forge fixture <fixture@example.invalid>` for commits.
The fixture builder records the initial commit and content digest.

`counter-service` contains `src/counter.py` with `increment(value)` incorrectly
returning `value + 2`, `src/format.py`, `tests/test_counter.py`,
`tests/test_format.py`, and immutable grader `tests/fixture_checks.py`. The task is:
"Make increment add one; preserve formatting behavior; add a boundary assertion
for -1; change only src/counter.py and tests/test_counter.py." Its first scripted
worker patch intentionally changes `+ 2` to `+ 0`; the failed check is the ordinary
failure to investigate and repair.

`split-catalog` contains independent `alpha/value.txt` and `beta/value.txt`, each
initially `old`, a shared `tests/fixture_checks.py`, and `README.md`. Alpha's task
sets only `alpha/value.txt` to `alpha-v2`; beta's sets only `beta/value.txt` to
`beta-v2`. A third task also reserves `alpha/value.txt`. The integration brief is
"checkpoint both settled writer changes only." Copies `catalog-A` and `catalog-B`
are used for separate-run concurrency and contain the same relative paths.

`review-gates` contains `src/range.py` whose inclusive range omits the upper bound,
tests covering only an interior value, and immutable grader
`tests/fixture_checks.py`. The planning brief requires lower, upper, reversed and
equal-bound cases. The implementation brief fixes the inclusive contract. The
review brief is read-only and asks for evidence-backed contract findings without
naming a required finding. A separate trivial task changes the exact typo `teh
result` to `the result` in `docs/result.md`.

Project policy exposes agents only these exact named checks (agents never choose
argv):

| Name | Effect class | Frozen behavior |
| --- | --- | --- |
| `unit` | worktree-exclusive check | `python -I -B tests/fixture_checks.py`; emits one `FORGE_EVAL_REPORT_V1` line bound to fixture/case version |
| `slow-unit` | worktree-exclusive check | `python -I -B tests/fixture_checks.py --barrier-file .forge-acceptance/slow-unit.release`; it records `.forge-acceptance/slow-unit.entered`, waits for the harness-created release file, then performs the same assertions |

Fixture version 2 places the barrier in the ignored, reserved `.forge-acceptance`
directory. It is separate from the owner-private `.forge` mutation store, so a
Docker check never needs access to that store. The barrier directory is
fixture-control state outside every agent's allowed paths. Before admission the
harness prepares a sticky, check-writable directory on POSIX and removes both
fixed files, failing if cleanup cannot be confirmed. The grader creates
`slow-unit.entered` atomically; the harness observes that marker before making
ordering assertions and atomically creates `slow-unit.release` to continue. The
fixed policy argv and marker protocol contain no caller- or agent-selected path,
shell text or environment value. Bounded process supervision supplies timeout and
cleanup; sleeps are not used as evidence that the barrier was entered.

`checkpoint` is not a named command. It is Forge's controlled Git commit tool,
invoked with the fixed message `forge: v0.2 fixture checkpoint` after acquiring a
worktree-wide checkpoint barrier. Agents cannot supply Git argv. Its operation
identity, barrier events, candidate tree and receipt are recorded separately from
named-check evidence.

The grader is outside every writer's allowed paths, parses candidate files without
importing arbitrary candidate code, and checks exact content plus declared cases.
Checks snapshot grader and candidate before/after and reject drift, malformed,
duplicate, missing, cancelled or truncated reports. Each repository has its own
scoped check resources; only an explicit same-resource test serializes them.

## Common evidence contract

Each scenario emits an immutable manifest with scenario/fixture version; run,
logical-task, attempt, operation and worktree identities; task DAG and ownership
reservations; frozen profile/envelope and policy digests; candidate commit/tree
and generated-input digest; provider/client/auth/billing/requested/effective route;
state/event sequence; tool admission, denial and durable receipt links; named
command/version/environment/outcome; handoff, findings and decisions; approvals
with run version and evidence digest; and usage coverage. Usage reports measurable
tokens, duration, tool calls, attempts, primary turns, wait/delegation time, repairs
and fallback reasons. Missing token, quota, cost or charge telemetry is `unknown`,
never zero. API cost, subscription allowance and possible provider charge are
separate fields. Logs and transcripts are bounded and redacted.
