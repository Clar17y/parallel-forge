# Inspect subscription tasks

Open a run and select the **Tasks** section to view **Subscription tasks**.
The inspector stays mounted while switching sections, but its panel is hidden
unless Tasks is selected; a `#subscription-tasks` deep link opens that section.
Select a task to load its attempts. The view shows its parent, dependencies,
owned paths, current scheduler status, pending stop requests and unsettled
effects. The candidate epoch identifies the candidate generation being observed.

Each attempt shows the requested and effective provider, client, model, effort,
authentication mode and billing mode. Missing measurements display **Unknown**.
An API cost estimate is not a subscription charge or proof of included-allowance
usage. The adjacent **Subscription usage** view shows primary shares of measured
input/output/duration, with primary and overall measurement coverage. Missing
measurements remain unknown; a partial measured share is not an overall share.

The inspector refreshes five seconds after each completed read. A slow read
finishes before another automatic read starts; the last snapshot stays visible
while refreshing. Use **Refresh tasks** or **Refresh attempts** for an immediate read.
Tasks and attempts have separate page controls; opening one task does not load
every attempt in the run. Legacy runs remain inspectable in the existing cockpit
and are identified as having no subscription tasks.

The authenticated read endpoints are:

- `GET /api/runs/{run_id}/subscription-tasks`
- `GET /api/runs/{run_id}/subscription-tasks/{task_id}/attempts`

Both accept `offset` (0–1,000,000) and `limit` (1–100, default 25). Responses
include `has_more`; a missing run or foreign/missing task returns 404. Each page
uses a consistent database snapshot. Pages refreshed at different times may
reflect later scheduling changes.

Select a specialist task to pause, cancel or resume it. Enter a reason; the action
uses the run/task versions from the displayed snapshot and an idempotency key.
The primary coordinator uses the existing run controls. Run stops prevent task
resume, and terminal runs cannot receive task controls.

**Pause requested** and **Cancellation requested** mean that termination and
controlled effects still need reconciliation. **Paused** requires the audited
receipt and durable settlement to agree. Resume uses that pause receipt; missing
or inconsistent evidence never offers a resume action. A paused task may retain
path ownership even after releasing execution capacity. Resuming a pending
decision and queuing a new provider attempt are distinct outcomes; neither
establishes that quota is available.

A task deferred by exhausted quota can be paused and resumed after its attempt
has settled. Resume preserves the quota block, existing work and budgets; the
scheduler rechecks eligibility. If exhaustion arrives during a task or run pause,
its durable observation permits later deferral without an extra repair debit.
**Waiting for a decision** means the individual pause was removed but an existing
scope decision is still required. It does not make the task eligible to launch.

A stale version refreshes the task and requires a new deliberate action. An
unconfirmed response offers **Retry same request**, preserving the original body
and key even if another tab updates the run. Successful controls return a durable
receipt and refresh the inspector. A new read after restart obtains the latest
audited control and its settlement status.

The mutation endpoint is
`POST /api/runs/{run_id}/subscription-tasks/{task_id}/controls`, with operator
authentication, CSRF, `Idempotency-Key`, and a closed body containing `action`,
`expected_run_version`, `expected_task_version`, `reason`, and (only for resume)
`pause_receipt_id`. Reasons are nonblank and at most 512 UTF-8 bytes. The local CLI
calls the same service:

```text
forge subscription-tasks control --action pause --run-id RUN_UUID --task-id TASK_UUID --expected-run-version 7 --expected-task-version 4 --reason "Inspect ownership" --idempotency-key task-pause-001
forge subscription-tasks control --action resume --run-id RUN_UUID --task-id TASK_UUID --expected-run-version 7 --expected-task-version 5 --pause-receipt-id PAUSE_RECEIPT_UUID --reason "Continue approved work" --idempotency-key task-resume-001
```

Use actual observed versions and UUIDs. Local checks cover queued, active and
settled historical attempts, including quota deferral and pending scope decisions.
Independent task-control review findings have been repaired and rechecked.
Worker-specific feedback/steering and complete browser acceptance remain v0.2
work in progress. The user's task-specific workflow replaces further separate AI
gates with implementation, verification and self-review by the Astra primary.
No inspection action grants execution or approval authority.

The run and global usage views call `GET /api/subscription-usage` with
`include_assessment=true` and the same `offset`/`limit` bounds; `run_id` is optional.
Workload totals cover all admitted attempts in the selected scope, while outcome
details follow complete groups on the current page. **Recorded wait until next
primary admission** includes scheduling delay and shows continued, unfinished,
ended and unknown intervals. Repair counts come from the debit ledger; quota
deferral is not a repair. Outcome details distinguish source-verified records,
matching decision applications, completed handoffs and tasks accepted by their
primary. These are not human approvals. The link **Inspect tasks and attempts**
opens this inspector, retaining access to prior attempts and evidence after
reassignment. Refreshes at different times may show later scheduling changes.
