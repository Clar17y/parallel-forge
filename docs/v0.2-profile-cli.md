# Local profile CLI

The privileged local operator can inspect and edit immutable subscription
profiles without a browser session or provider key. Commands use the existing
versioned profile service, durable mutation receipts, and a stable local actor
(`local_cli`) for audit records.

Read-only commands:

```text
forge profile list
forge profile show --profile-id PROFILE_UUID --version 1
forge profile project-show --project-id PROJECT_UUID
```

Mutations require a JSON file and an explicit idempotency key:

```text
forge profile create --file profile.json --idempotency-key profile-create-1
forge profile append --profile-id PROFILE_UUID --file profile-v2.json \
  --idempotency-key profile-append-2
forge profile project-select --project-id PROJECT_UUID --file selection.json \
  --idempotency-key project-select-1
```

`profile.json` follows the closed `ProfileBody` schema. `profile-v2.json`
adds `expected_current_version`; `selection.json` contains `profile_id`,
`profile_version`, and either both `expected_profile_id` plus
`expected_profile_version`, or neither. Unknown fields, malformed values, and
files larger than 256 KiB fail with a sanitized nonzero error. Retrying an
identical mutation key replays its receipt; reusing it with changed input
fails. JSON output is stable and suitable for scripts.

The CLI owns configured local database credentials and disposes its database
engine on every success and failure path. Its audit source is `local_cli`,
distinct from the web session source `web_session`; the local actor has no
fabricated session identifier. Profiles describe requested configuration and
do not verify runtime provider support.

## Subscription client setup and readiness

Forge uses the official client's existing subscription session. It does not ask
for, copy, or persist provider credentials, API keys, purchased credits, or
overage settings. Login remains an operator-owned action inside the official
client:

- Codex: run `codex login`, select the intended personal ChatGPT account, and
  keep that account in the configured Codex home.
- Claude: run `claude auth login`, then verify the selected subscription session
  with `claude auth status`. Forge's launch environment excludes ambient
  `ANTHROPIC_API_KEY` and other paid cloud credential routes.
- Google: sign in inside the official Antigravity client and configure its
  `antigravity_cli` installation. Operator trust permits the configured route
  while retaining the `approved_tools_unproved` warning: native tools may remain
  available. Actual route, callback, quota and lifecycle checks still apply.

Set `FORGE_SUBSCRIPTION_INSTALLATIONS_PATH` to the absolute schema-version-2
manifest shared by the API, worker and CLI; use the
[installation examples](v0.2-upgrade.md#operator-subscription-installations).
The default `FORGE_SUBSCRIPTION_CLIENT_TRUST=operator` trusts the configured
client/login and selected route. Missing capability reports and ordinary client
updates do not impose a new admission gate. Restart the worker after changing
its installation configuration so its executable binding and registrations reload.
Create/select the desired immutable project profile in **Subscription profiles**
or with the commands above before starting a new task. Existing runs keep their
frozen profile and route history.

DeepSeek and new paid-API integration are outside v0.2. Where configured, the
routine fallback is Codex subscription `gpt-6-luna` / medium. Advisory JEV search
ranking is separate, optional and off by default; it is not a provider fallback.

Inspect installation metadata without contacting a provider:

```text
forge subscription-runtime status --format text
forge subscription-quota list
```

The runtime command reads the latest PostgreSQL worker projection and explains
the configured route, admission policy, current reason and quota gate. Its default
`--format json` remains stable for scripts. These commands do not launch a client,
probe quota, reserve an attempt, contact a provider or change account state.

`quota=unknown` is neither a zero balance nor an availability claim.
`quota=eligible-to-attempt` is not a remaining-allowance balance. A blocked
quota shows only retained reset/next-probe timestamps; the remedy never suggests
adding credits or silently switching to paid API billing.

The Subscription profiles page shows the same safe projection. After completing
login or changing official-client configuration, choose **Refresh subscription
readiness**. That refresh is shared with other open Forge tabs; the normal
five-second refresh remains a fallback. Operator-trusted clients show
`operator_trusted` / **Ready to attempt** and Antigravity retains
`approved_tools_unproved`. This is not proof of native-tool isolation or remaining
allowance. Missing/misconfigured installations, unsupported routes, unavailable
workers and known quota blocks remain actionable.

## Optional verified admission

Choose `FORGE_SUBSCRIPTION_CLIENT_TRUST=verified` only when the older evidence
admission policy is desired. This is not required for personal-use acceptance;
the production verified-mode composition supports Codex and Claude, not the
legacy Gemini ACP or Antigravity adapters.

```text
forge subscription-capabilities status
forge subscription-capabilities verify --client codex_app_server --installation 1 --scope astra-primary
```

`status` reads installation metadata and retained evidence. `verify` runs a
providerless official-client harness, retains an offline artifact and reports
missing proof classes; it cannot publish runtime authority. In this optional
mode, exact, unexpired evidence is required for the selected scopes.
Publishing new capability evidence is separate because it makes a
bounded provider contact. Run `status` and `verify` first, then use the exact
installation, client, and scope only after the operator authorizes that live
check:

```text
forge subscription-capabilities publish --authorize-provider-contact --client codex_app_server --installation INDEX --scope NAME
```
