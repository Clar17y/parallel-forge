# Local profile CLI

The privileged local operator can inspect and edit immutable subscription
profiles without a browser session or provider key. Commands use the existing
versioned profile service, durable mutation receipts, and a stable local actor
(`local_cli`) for audit records.

Read-only commands:

```text
forge profile list
forge profile show --profile-id PROFILE_UUID --version 1
forge profile project-show --project-id PROJECT_UUID
```

Mutations require a JSON file and an explicit idempotency key:

```text
forge profile create --file profile.json --idempotency-key profile-create-1
forge profile append --profile-id PROFILE_UUID --file profile-v2.json \
  --idempotency-key profile-append-2
forge profile project-select --project-id PROJECT_UUID --file selection.json \
  --idempotency-key project-select-1
```

`profile.json` follows the closed `ProfileBody` schema. `profile-v2.json`
adds `expected_current_version`; `selection.json` contains `profile_id`,
`profile_version`, and either both `expected_profile_id` plus
`expected_profile_version`, or neither. Unknown fields, malformed values, and
files larger than 256 KiB fail with a sanitized nonzero error. Retrying an
identical mutation key replays its receipt; reusing it with changed input
fails. JSON output is stable and suitable for scripts.

The CLI owns configured local database credentials and disposes its database
engine on every success and failure path. Its audit source is `local_cli`,
distinct from the web session source `web_session`; the local actor has no
fabricated session identifier. Profiles describe requested configuration and
do not verify runtime provider support.
