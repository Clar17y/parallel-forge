# Forge v0.2: subscription-backed multi-provider agent runtime

## Outcome
An operator can run Forge planner/developer/reviewer roles through authenticated official Codex, Claude and Google coding clients using an existing subscription, select explicit role routes, and see which provider/mode executed each attempt. API-key mode remains explicit. Login/quota failure never silently enables API billing or substitutes a model/provider.

The product target is the working standard of the local multi-provider framework
used to build Forge: a user-selected primary orchestrator with specialist workers,
bounded delegation, independent review when useful, and evidence-backed acceptance.
Connecting three clients alone does not satisfy v0.2. This is an operational and
capability target; identical answer quality cannot be guaranteed across clients or
model versions and must be assessed on representative coding tasks.

## Required agent setup

Provide an editable, versioned operator profile with these initial role preferences,
transcribed from the installed framework on 10 September 2026:

| Responsibility | Preferred route | Explicit fallback or escalation |
| --- | --- | --- |
| Primary orchestration and final acceptance | User-selected provider, model and effort | Never silently change the primary |
| Routine delegated implementation | Gemini, `gemini-3.8-flash-medium` | OpenAI Luna medium when the route is exhausted, unavailable or blocked and ownership is safe |
| Complex bounded implementation | OpenAI Terra low | Planning/correctness specialist when needed |
| Independent integrated review | Claude `claude-opus-5`, medium | OpenAI Astra low when Claude is unavailable |
| Planning and adversarial test design | OpenAI Sol low | Scoped higher-effort analysis when justified |
| Exploration, documentation, refactor audit and verification | OpenAI Luna medium | Task-specific escalation |
| Security and distinct high-risk correctness questions | OpenAI Sol high | Explicit reassessment for unresolved findings |

These are requested profile identifiers, not a claim that each official client
exposes the same model aliases as this development host. Setup must resolve and
verify model and effort support against the installed client and signed-in account.
An unavailable preference requires an explicit operator-approved mapping or remains
unavailable; never label a different model as the requested model. Exceptional
maximum-effort review is opt-in. High-effort Claude review requires a recorded
complexity reason. No implicit Sonnet/Fable substitution.

Forge must support the following working behavior:

- The primary owns scope, architecture, decomposition, integration and acceptance;
  it can complete small, well-understood repairs directly.
- Workers own complete bounded outcomes through investigation, implementation,
  focused tests, routine repairs and self-review. Contracts include acceptance
  criteria, explicit file ownership, context and validation commands. Handoffs
  include changed paths, candidate identity, actual results and remaining concerns.
- Independent tasks may run concurrently within configured limits. Overlapping
  writers are prevented, including directory descendants. A fallback cannot take
  ownership until the previous writer has stopped or been safely reconciled.
- Each delegated role receives its own instructions, context, model/effort and tool
  permissions. Child delegation is controlled by Forge policy, not unrestricted
  provider-native spawning. Review is independent of the writers and read-only.
- Review and verification are proportional to risk: prefer one coherent integrated
  review where useful, avoid reviews after every small edit, and reassess repeated
  repair failures. Preserve mandatory project acceptance gates.
- Reuse valid evidence when candidate inputs and conditions still match. Show why
  a check must rerun. Checkpoint pushes do not automatically authorize full CI;
  this project's full runs and merges require their separate human approvals.
- Persist role routes, effective model/effort, attempt state, findings, evidence,
  ownership, fallback reasons and handoffs so work survives worker/API restarts.
- Operator setup supports existing local subscription sign-in for all three
  providers, clear login/quota status and deliberate routing changes. Do not
  require per-call API keys for subscription routes or conceal paid API fallback.

## Scope and ownership boundaries
Keep Forge's AgentGateway/AgentRequest/AgentResult and durable orchestration. Extract the ADK-named invocation/tool envelope into Forge-owned contracts; retain Google ADK as one implementation. Production worker and live evaluations use the same runtime factory. Repository-controlled tools remain in ControlledToolService and execute through a per-attempt bound broker; CLI built-in shell/write/network/subagent tools are disabled, not merely discouraged in prompts. Tool effects keep operation intent and evidence admission.

Personal development routing remains installed externally. Import role/provider/model/effort preferences only as an explicit versioned operator profile with capability validation. Never import development bypass flags or arbitrary CLI argv/commands. Independent reviewer role uses separate invocation and permitted read-only tools. Review selection remains proportional rather than one review per small edit.

## Delivery slices
1. Provider-neutral invocation/tool contracts and explicit auth/billing capabilities, with unchanged ADK behavior and matching gateway regression evidence.
2. Official-client supervisor and Forge tool broker: fixed executable/argv, isolated configuration, authenticated per-attempt tools, bounded streams, process-tree cancellation, durable attempt receipt, and interrupted-session reconciliation. Fake clients prove no escape, no late-result acceptance, no untracked retry.
3. Codex app-server adapter with managed ChatGPT auth, dynamic tools (version/capability gated), structured output, usage/quota notifications and interruption. No credential extraction. Refuse API auth when subscription is selected.
4. Claude official SDK/client adapter with managed subscription auth, no built-in tools, a mandatory tool gate, isolated settings and bounded interruption. Do not assume allowed_tools alone restricts capabilities.
5. Google official client adapter: establish whether installed agy supports required structured/tool callback controls; otherwise use supported Gemini CLI with cached Google login. Do not pretend agy and gemini are interchangeable. If client cannot enforce the contract, surface unsupported capability rather than unrestricted execution.
6. Implement the required agent setup above: primary and specialist role profiles, durable bounded delegation, ownership/concurrency enforcement, policy-approved fallback and proportional review/evidence reuse. Add operator setup/status UI/CLI; show installed client, signed-in state, effective model/effort, model availability, quota/exhaustion, explicit subscription/API billing mode and configuration errors. No keys in browser, logs or policy. Use supported login UI rather than copying tokens.
7. Deterministic end-to-end/recovery and focused native Windows/Linux child-process checks, one integrated independent review and scoped correctness/security checks for remaining risks. Live subscription tests require separately scoped user authorization; full CI requires per-run approval.

## Billing and durability decisions
Subscription plan price is not per-run measured cost. Keep token/duration/tool limits when measurable; expose unknown metrics honestly. Require an explicit subscription budget policy for absent cost/token telemetry; do not zero-fill unknown usage. Quota exhausted is distinct from auth failure, unsupported model, outage and uncertain process termination. All retries retain attempt identity and budget, and any provider fallback must be frozen in approved policy.

## Acceptance
All three named provider routes run valid role output through Forge-controlled tools without per-call API keys; supported authenticated-client checks distinguish real capability from mocks. Existing three approval gates and durable crash/recovery semantics remain. Onboarding can report a missing client/login/profile without crashing the entire API. The final ledger distinguishes deterministic evidence from live opt-in proof.

Demonstrate a representative repository task with the selected primary delegating
implementation to Gemini, obtaining an independent Claude review when warranted,
and using an OpenAI specialist, with recorded effective models and real test
evidence. Separately demonstrate a small repair without unnecessary review/full CI,
safe fallback after quota/unavailability, rejection of overlapping writers, and
restart/cancellation recovery without duplicate edits or late-result acceptance.
Deterministic fixtures establish failure paths; authorized live client runs must
establish actual subscription access and tool capability for each provider.
Compare the representative task's outcome, review findings and verification with
the local framework's acceptance criteria. Document unsupported capabilities and
operator-approved model mappings; do not claim full parity while a required route
or behavior is missing. Development CLI bypass flags are not a runtime requirement:
equivalent useful coding work must pass through Forge's controlled tools.

## Sources / unresolved details
Verified documentation on 9 September 2026:

- [Codex app-server](https://learn.chatgpt.com/docs/app-server): managed ChatGPT login, dynamic tool callbacks and quota status. Local client0.153.4 schema generation confirms dynamic-tool protocol availability; no model call was made.
- [Claude SDK permissions](https://code.claude.com/docs/en/agent-sdk/permissions) and [Python SDK](https://code.claude.com/docs/en/agent-sdk/python): explicit tool controls, hooks and interruption. Installed CLI2.1.263 supports disabling built-in tools.
- [Claude subscription SDK update](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan): the June15 billing changes were paused; do not treat the historical monthly-credit text as active policy.
- [Gemini CLI authentication](https://geminicli.com/docs/get-started/authentication/) and [policy engine](https://geminicli.com/docs/reference/policy-engine/): cached sign-in and policy-controlled tools. `agy` is installed here; `gemini` is not. Their capabilities must be evaluated independently.

These are design inputs, not live integration acceptance. Subscription runtimes
are not implemented by this document. Protocol/version/tool-disable capabilities must be verified against installed official clients before enabling a route. The runtime architecture must not depend on unexported provider internals or raw OAuth endpoint emulation.
