# Forge v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** Build the complete local-first Forge v0.1 vertical slice: a durable agentic engineering control plane with a dashboard, bounded autonomous remediation, controlled GitHub pull-request actions, and exact human approval gates.

**Architecture:** Implement a Python modular monolith with separate FastAPI and worker entry points communicating through PostgreSQL commands, leases, events, and operation intents. Put Google ADK, local tools, Docker, Git, and GitHub behind Forge-owned ports; expose the real workflow through a Next.js 16 dashboard using REST and Server-Sent Events.

**Tech Stack:** Python 3.14, uv, FastAPI, Pydantic 2, SQLAlchemy 2, Alembic, asyncpg, Google ADK 2.5.0, httpx, PostgreSQL 17, OpenTelemetry, pytest, Ruff, mypy, Node.js 24, npm workspaces, Next.js 16 App Router, React 19, TypeScript, Tailwind CSS, Vitest, Testing Library, Playwright.

## Global Constraints

- Python is exactly major/minor 3.14 for local development and CI.
- Node.js is at least 24.0.0 and below 25.0.0; npm is the JavaScript package manager.
- PostgreSQL is the system of record from the first executable workflow. Do not add SQLite, Redis, Celery, or an in-memory production fallback.
- The API and worker are separate entry points and communicate through PostgreSQL, including in local development.
- State changes and causal events commit in one transaction. Every side effect has a durable idempotent intent before invocation and a durable outcome or reconciliation record afterwards.
- Google ADK remains behind AgentGateway. ADK types never enter Domain or Application interfaces.
- Planner is read-only. Developer writes only inside the managed worktree. Reviewer is a fresh read-only execution. No model-driven agent receives push, PR-write, merge, policy-write, approval, Forge-database, or credential capabilities.
- Only the deterministic Release Controller can push, create/update a PR, or merge.
- Plan, PR, and merge approvals bind exact evidence. Merge approval binds exact head and observed base commits and is invalidated by any material change.
- A Forge-managed merge must pass GitHub's atomic expected-head precondition and GitHub-enforced strict up-to-date-base protection or a merge queue.
- Local and remote remediation each default to at most three cycles. Starting an attempt consumes a cycle even if it creates no commit.
- Every repository-controlled bootstrap, install, migration, seed, build, lint, typecheck, and test command uses a policy-versioned argument vector and the configured runner.
- Docker is the default runner: non-root, worktree-only mount, no Docker socket, no network unless approved, and bounded CPU, memory, duration, and output. Trusted host mode is explicit and visibly weakens containment.
- Agents choose named tools and checks, never arbitrary shell strings.
- All paths are canonicalized and contained. Reject traversal, symlink, junction, reparse-point, and worktree-name collisions.
- Environment files are explicitly enumerated. Secret-designated paths are never readable through agent repository tools and their values are never logged.
- Worktree/database teardown is a separate explicit command. Keep branches by default.
- The dashboard and API share one loopback origin. Mutations require an authenticated operator session and CSRF token; approvals also require a single-use evidence-bound challenge.
- REST handles commands and historical queries. Server-Sent Events handles live updates. Do not add WebSockets in v0.1.
- Persist audit, artifact lineage, validation, review, provider/model, token, estimated cost, duration, and tool-call metadata. Never persist hidden model reasoning or unrestricted environment dumps.
- Tests use deterministic fake agents and GitHub by default. Paid-model and live-GitHub smoke tests are opt-in and credential-gated.
- Do not add GCP, Cloud Run, Terraform, Kubernetes, Kafka, custom MCP services, multi-tenancy, or a plugin marketplace.
- Follow test-driven development: add one focused failing test, observe the expected failure, implement the smallest behavior, rerun the focused test, run the affected suite, then commit.
- Each task receives an independent specification review and code-quality review before the next task begins.
- This plan authorizes local implementation only. It does not authorize creating, pushing, or merging a Forge pull request.

~~~python
from pathlib import Path
from typing import Literal
from platformdirs import user_data_path
from pydantic import model_validator
from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_prefix="FORGE_", env_file=".env", extra="ignore")

    process_role: Literal["api", "worker", "cli"] = "api"
    database_url: str = "postgresql+asyncpg://forge:forge@127.0.0.1:5435/forge"
    data_root: Path = user_data_path("Forge", "Parallel")
    bind_host: str = "127.0.0.1"
    api_port: int = 8000
    web_origin: str = "http://127.0.0.1:3000"
    allow_remote: bool = False

    @property
    def artifact_root(self) -> Path:
        return self.data_root / "artifacts"

    @model_validator(mode="after")
    def enforce_local_only(self) -> "Settings":
        if self.bind_host not in {"127.0.0.1", "::1", "localhost"} and not self.allow_remote:
            raise ValueError("remote exposure requires a later authentication design")
        return self
~~~

~~~python
from forge.application.services.state_engine import StateEngine
from forge.domain.errors import InvalidTransition

def new_run() -> RunSnapshot:
    return RunSnapshot(id=uuid4(), project_id=uuid4(), task_id=uuid4())


def test_happy_path_reaches_pr_approval() -> None:
    engine = StateEngine()
    run = new_run()
    for target in (
        RunState.PLANNING,
        RunState.AWAITING_PLAN_APPROVAL,
        RunState.PREPARING_WORKTREE,
        RunState.IMPLEMENTING,
        RunState.VALIDATING,
        RunState.REVIEWING,
        RunState.AWAITING_PR_APPROVAL,
    ):
        run = engine.transition(run, target)

    assert run.state is RunState.AWAITING_PR_APPROVAL
    assert run.version == 7


def test_cannot_publish_without_pr_approval_state() -> None:
    with pytest.raises(InvalidTransition):
        StateEngine().transition(new_run(), RunState.PUBLISHING_PR)


def test_pause_and_resume_restore_the_exact_state() -> None:
    engine = StateEngine()
    run = engine.transition(new_run(), RunState.PLANNING)
    paused = engine.pause(run)
    resumed = engine.resume(paused)

    assert paused.state is RunState.PAUSED
    assert paused.suspended_state is RunState.PLANNING
    assert resumed.state is RunState.PLANNING
    assert resumed.suspended_state is None


def test_terminal_run_cannot_advance() -> None:
    cancelled = StateEngine().transition(new_run(), RunState.CANCELLED)
    with pytest.raises(InvalidTransition):
        StateEngine().transition(cancelled, RunState.PLANNING)
~~~

~~~python
from dataclasses import dataclass, replace
from enum import StrEnum
from uuid import UUID


class RunState(StrEnum):
    CREATED = "CREATED"
    PLANNING = "PLANNING"
    AWAITING_PLAN_APPROVAL = "AWAITING_PLAN_APPROVAL"
    PREPARING_WORKTREE = "PREPARING_WORKTREE"
    IMPLEMENTING = "IMPLEMENTING"
    VALIDATING = "VALIDATING"
    REVIEWING = "REVIEWING"
    REMEDIATING = "REMEDIATING"
    AWAITING_PR_APPROVAL = "AWAITING_PR_APPROVAL"
    PUBLISHING_PR = "PUBLISHING_PR"
    MONITORING_PR = "MONITORING_PR"
    AWAITING_HUMAN_INTERVENTION = "AWAITING_HUMAN_INTERVENTION"
    AWAITING_MERGE_APPROVAL = "AWAITING_MERGE_APPROVAL"
    MERGING = "MERGING"
    PAUSED = "PAUSED"
    COMPLETED = "COMPLETED"
    FAILED = "FAILED"
    CANCELLED = "CANCELLED"


@dataclass(frozen=True, slots=True)
class RunSnapshot:
    id: UUID
    project_id: UUID
    task_id: UUID
    state: RunState = RunState.CREATED
    version: int = 0
    suspended_state: RunState | None = None
    local_remediation_count: int = 0
    remote_remediation_count: int = 0

    def with_state(self, state: RunState, suspended_state: RunState | None = None) -> "RunSnapshot":
        return replace(self, state=state, suspended_state=suspended_state, version=self.version + 1)
~~~

~~~python
class OperationExecutor:
    def __init__(self, operations: OperationRepository) -> None:
        self._operations = operations

    async def execute(self, request: OperationRequest, adapter: OperationAdapter) -> OperationOutcome:
        intent = await self._operations.begin(request)
        if intent.status is OperationStatus.SUCCEEDED:
            return intent.to_outcome()
        if intent.attempt > 0:
            outcome = await adapter.reconcile(intent)
        else:
            outcome = await adapter.invoke(intent)
        await self._operations.complete(intent.id, outcome)
        return outcome
~~~

~~~python
from google.adk.agents import LlmAgent
from google.adk.runners import Runner
from google.adk.sessions import InMemorySessionService
from google.genai import types


class AdkRuntime:
    async def invoke(self, request: AdkInvocation) -> AdkInvocationResult:
        agent = LlmAgent(
            name=request.agent_name,
            model=request.model,
            instruction=request.instruction,
            include_contents="none",
            output_schema=request.output_schema,
            tools=list(request.tools),
        )
        sessions = InMemorySessionService()
        runner = Runner(
            app_name="forge",
            agent=agent,
            session_service=sessions,
            auto_create_session=True,
        )
        content = types.Content(role="user", parts=[types.Part(text=request.user_payload_json)])
        events = []
        async for event in runner.run_async(
            user_id=request.user_id,
            session_id=request.session_id,
            new_message=content,
        ):
            events.append(event)
        return AdkInvocationResult.from_events(events, expected_author=request.agent_name)
~~~

- [ ] **Step 5: Implement startup reconciliation before command claiming**

Worker startup:

1. acquires a singleton recovery lease;
2. finds expired run/command leases;
3. loads every pending/needs_reconciliation operation;
4. invokes the operation-type reconciler against authoritative local/GitHub state;
5. persists outcomes and causal events;
6. repairs or releases leases;
7. moves ambiguous integrity cases to intervention;
8. releases recovery lease;
9. begins ordinary command claiming.

Branch deletion requires a separate boolean confirmation and is false by default.
